# Практическая работа: 2–3-дерево

## Что реализовано
- `AbstractSearchTree` — полиморфный базовый интерфейс для интеграции с иерархией из практической работы №2.
- `TwoThreeTree` — полноценное сбалансированное дерево поиска порядка 3 (в узле один или два ключа, два или три ребенка).
- Построение из `std::vector<int>`, поиск, вставка, удаление с перебалансировкой, объединение множеств, ближайшие больший/меньший ключи, `m` следующих.
- Операторы `<<` и `>>` для консоли и файловых потоков; уровневое текстовое представление.
- `validate()` проверяет диапазоны ключей, степень вершин, равную глубину листьев, размер.
- Тесты со сравнением со `std::set` на 25 000 случайных операций.

**Важно:** в предоставленной ссылке на Викиконспекты описана модификация 2–3-дерева, где ключи находятся в листьях, а внутренние узлы хранят разделители. Здесь применено другое корректное представление — ключи хранятся и во внутренних узлах, и в листьях. Это классическое B-дерево с максимум двумя ключами в узле. В сериализации каждый ключ присутствует один раз.

## Ввод / вывод

Формат: `N K1 K2 ... KN`. Вводимые значения могут идти в произвольном порядке. Дубликаты игнорируются. Запись содержит размер итогового множества и все ключи в порядке возрастания.

Пример `tree.txt`:

```
7 10 20 5 15 30 25 40
```

```cpp
TwoThreeTree tree;
std::ifstream in("tree.txt");
in >> tree;
std::cout << tree << '\n'; // 7 5 10 15 20 25 30 40
std::ofstream out("result.txt");
out << tree;
```

Если чтение данных прервалось или получено отрицательное N, существующее дерево не изменяется.

## Пример состояния дерева

```text
7 10 20 5 15 30 25 40
```

После ввода используйте команду `2` в меню для вывода ключей и всех уровней дерева.

## Сложность

| Операция | Время | Дополнительная память |
|---|---|---|
| contains, insert, erase | O(log n) | O(log n) рекурсивный стек для insert/erase |
| successor, predecessor | O(log n) | O(1) |
| nextElements(x, m) | O(log n + r), r = min(m, количество следующих) | O(log n + r) |
| Построение из n элементов | O(n log n) | O(n) |
| merged двух деревьев размеров n и k | O((n+k) log(n+k)) | O(n+k) |
| `<<` / `>>` | O(n) для вывода / O(n log n) для ввода | O(n) |

При оценке следующего набора из `r` ключей обход пропускает ветви, где все значения не превышают `x`, и прекращает обход после `r` результатов. Выход содержит не более `m` ключей.

## Обзор альтернатив

| Структура | Поиск | Изменение | Следующие m | Особенности |
|---|---|---|---|---|
| 2–3-дерево | O(log n) | O(log n) | O(log n + m) | Строгий баланс, 2 или 3 потомка |
| AVL-дерево | O(log n) | O(log n) | O(log n + m) | Очень строгое балансирование, бинарные узлы |
| Красно-чёрное дерево (`std::set`) | O(log n) | O(log n) | O(log n + m) | Частый выбор для структур в ОЗУ |
| B-дерево / B+ дерево | O(log_B n) обращений к блокам | O(log_B n) | O(log_B n + m/B) чтений блоков | Эффективно для диска и больших наборов |
| Декартово дерево (treap) | O(log n) ожидаемо | O(log n) ожидаемо | O(log n + m) ожидаемо | Рандомизированный баланс |
| Хеш-таблица | O(1) в среднем | O(1) в среднем | Не поддерживает эффективно | Нет упорядоченности и соседей |
| Отсортированный массив | O(log n) | O(n) | O(log n + m) | Быстрые диапазоны без частых вставок |

Вывод: для частых вставок/удалений и упорядоченных диапазонных запросов подходит 2–3-дерево. Для типового C++ кода проще `std::set`, для дисковых индексов — B+ дерево. Для поиска без требования упорядоченности подходит хеш-таблица.
